# Riora OS 機能一覧・使い方ガイド

最終更新: 2026-07-25
用途: 営業資料 / 導入マニュアル / 社内引き継ぎ 共通版
対象: Riora OS（銀座高級エステサロン向け接客OS）— スタッフアプリ + 管理者ダッシュボード

> 本ドキュメントはコードベースの実装状況を確認した上で作成しています。「未実装」と明記した項目は
> 構想・設計のみで実コードは存在しません。「実装済み・未デプロイ」は開発環境には存在するが本番へは
> まだ反映されていない機能です。営業資料としてご利用の際は、この2区分を混同しないようご注意ください。

---

## 1. Riora OS とは

スタッフの「接客」と経営者の「経営判断」を分離して支援する接客OS。

- **スタッフアプリ**: その場の接客に必要な事実情報のみを表示する。スコア・ランキング・他スタッフとの比較は一切行わない（安心して使えることを設計上の前提とする）。
- **管理者ダッシュボード**: 経営分析・スタッフ比較・売上/利益管理など、経営判断に必要な情報を集約する。

## 2. スタッフアプリ 機能一覧

5タブ構成（画面下部固定ナビゲーション）: **今日 / 顧客 / メモ / マイページ / 設定**

### 今日タブ（`/phase1`）

| 機能 | 内容 |
|---|---|
| **30秒ブリーフィング** | 出勤直後に必要な情報だけを30秒で把握できる要約画面。「次のお客様」表示・3行の注意事項・折りたたみ式の詳細情報・このあとの予約リストで構成される（v1.0.1で再設計） |
| 今日の予約一覧 | 本日の予約をカード形式で表示。タップでCustomer Bottom Sheetを開く |
| AI Timeline（顧客カード内） | 音声メモ・来店履歴から自動生成される4セクション要約・リスク検知・関係性スコア・派生イベント |

### 顧客タブ（`/customers`）

| 機能 | 内容 |
|---|---|
| **顧客一覧** | 「私のお客様」「全顧客」の担当軸タブ切り替え、名前・タイプ・担当者・施術名での検索 |
| 顧客検索 | 上記検索ボックス（自由入力・複数属性を横断） |

### Customer Bottom Sheet（顧客詳細シート）

顧客カードをタップすると開く、接客中に必要な情報を集約したパネル。

| 機能 | 内容 |
|---|---|
| **AI提案** | 離脱リスク・LINEフォロー・再来提案・商品提案・VIPフォロー・ホームケアフォロー・フェーズ別提案（新規/成長/継続/リスク/VIP）をルールベースで判定し最大3件表示。会話のきっかけとして提示するのみで、断定・命令はしない |
| **接客ヒント（ブログナレッジ連携）** | 顧客の肌タグ・音声AIタグと、承認済みブログ記事のキーワードを突き合わせ、該当する安全な質問文テンプレートを提示。一致が無い場合は一般的な質問文にフォールバック |
| **関連記事表示** | ホームケア購入商品と承認済みブログ記事を商品名で突き合わせ、タイトルのみ表示（本文・URLは非表示） |
| **生成理由表示** | AI提案・接客ヒント・LINE文面生成それぞれに「なぜこの提案か」を示すタグ（肌タグ一致／カテゴリ一致／関連記事一致／ホームケア商品一致／前回施術一致／購入履歴一致）を表示 |
| **LINEメッセージ生成（AI下書き）** | 顧客名・肌タグ・来店履歴・ホームケア購入商品・接客メモを元にClaude Haikuが自然な文面を生成。**生成→編集→コピーのみ**（送信APIは呼ばない。送信はスタッフ本人がLINEアプリから手動で行う） |
| **ホームケアメッセージ生成** | ホームケア商品ごとに使い方確認メッセージをAI生成 |
| **ホームケア履歴** | 購入済みホームケア商品一覧・使い方カード（商品カテゴリ別の接客ヒント）・前回購入からの経過日数 |
| **来店履歴** | 来店日・メニュー・担当者を一覧表示（デプロイ状況は6章参照） |
| 今日気をつけること | 音声メモ由来の触れない話題（NGトピック）・センシティブな顧客メモを自動抽出して表示 |
| 音声メモ再生・保存 | 接客中に録音した音声メモの保存・一覧 |

### メモタブ（`/memo`）

| 機能 | 内容 |
|---|---|
| **音声メモ** | 録音→文字起こし（Whisper）→AI解析→保存の一連のフロー |
| **音声AIタグ（insightTags）** | 音声メモの内容をAIが解析し、`voice_notes.insight_tags`として保存するタグ群（例: 乾燥の悩み・忙しい・イベント前 等）。直近10件分を集約し、接客ヒント・AI提案のナレッジ一致語彙としても利用する |
| AI自動要約 | 音声メモを5カテゴリ（悩み・要望・雑談等）に自動分類しcustomer_notesへ保存 |

### マイページ（`/me`）

他人比較・ランキングは一切行わない。表示は自分の**先月比**のみ。

| 表示項目 | 内容 |
|---|---|
| 先月比 指名 | 指名来店数の今月−先月の差分（件数） |
| 先月比 リピート率 | リピート率の今月−先月の差分（%ポイント） |
| **先月比 店販売上** | 店販売上（`retail_amount`合計）の今月−先月の差分。`+¥28,000`のように金額差で表示。今月・先月とも来店記録が無い場合は「計測中」 |
| 来店数差分 | 来店件数の今月−先月の差分（件数） |

> 表示は「今月の実数」ではなく、いずれも**先月との差分**です。実数（今月の売上額そのもの等）は表示しません。

### 設定タブ（`/menu`）

| 機能 | 内容 |
|---|---|
| メニュー実績 | 店舗全体のメニュー数・今月売上・90日リピート率・人気メニューランキング |
| 全機能紹介・使い方ガイド | アプリの操作説明（アコーディオン形式7セクション） |
| **ログアウト** | 画面最下部の赤いボタン。タップで確認ダイアログ（「ログアウトしますか？」）→確定で`supabase.auth.signOut()`実行後`/login`へ遷移。スタッフアプリ・管理者ダッシュボード共通のロジックを使用 |

## 3. セキュリティ・安心設計

Riora OSは、お客様情報を安心して扱えるよう、安全性を重視した設計になっています。

### お客様情報の保護

お客様情報は、サービス提供に必要な最低限の情報のみを扱い、安全に管理しています。
また、個人情報はAI処理とは分けて管理し、必要な範囲でのみAI機能が利用できる仕組みになっています。

### AI利用時の情報管理

AI機能は、お客様対応や提案作成をサポートする目的で利用しています。
不要な個人情報をAIに渡さない設計により、情報管理に配慮しています。

### 音声メモの安全利用

スタッフが残した音声メモは、接客履歴や引き継ぎをサポートするために活用されます。
必要な情報整理にのみ利用し、目的外での利用を防ぐ設計になっています。

### 安心して使える管理体制

操作やデータ管理は適切に管理され、店舗運営に必要な範囲で安全に利用できます。

### お客様への連絡管理

LINEなどのお客様への連絡は、スタッフが内容を確認・承認した上で送信する仕組みになっており、意図しない連絡を防止しています。

## 4. 管理者ダッシュボード 機能一覧

左サイドバー（デスクトップ）/ ハンバーガーメニュー（モバイル）構成。`admin@salon-riora.jp`でログインした場合のみ表示される。

| サイドバー項目 | 機能 |
|---|---|
| **ダッシュボード**（経営TOP） | 本日売上・目標進捗・次回予約率・DM→予約転換率・来店人数・客単価・リピート率(30/60/90日)・指名率・CSV取込状況を集約表示 |
| **売上分析** | ダッシュボード内: 月間売上/目標、着地予測、日別売上推移 |
| **利益分析** | ダッシュボード内: 利益(暫定)、損益分岐点、損益分岐までの残り、人件費率 |
| **スタッフ分析** | スタッフごとの月間売上・来店人数・客単価・指名率・リピート率・LTV・前月比成長率を5十音順カードで表示（ランキング・順位付けは行わない） |
| **稼働率分析** | ①スタッフ別稼働状況（今月来店数・今月売上・今月指名率・今月稼働率＋先月比較）・②曜日別来店数・③時間帯別来店数・④稼働分数推移。今月稼働率は`seat_capacity`未設定のため現状「データ未整備」表示 |
| **失客分析**（失客リスク管理） | 離脱予兆センター。失客リスクの高い顧客を検知・一覧表示 |
| **CSV取込** | 予約・来店実績CSVの取込（Dry Run確認→本取込）、取込履歴 |
| **ブログ管理** | サロンブログ記事のURL登録・承認フロー（AI提案・接客ヒント・LINE文面生成のナレッジ元） |
| **ナレッジ取込** | ブログ記事の一括CSV取込（タグ・カテゴリの統一語彙運用） |
| **メニュー管理**（メニューマスタ） | 施術メニューのCRUD（登録・編集・削除）、顧客タイプ別ターゲティング設定 |
| **店舗設定** | 売上目標・固定費・変動費率などの店舗経営パラメータ設定 |
| **LINE分析**（LINE管理） | チャット一覧・配信履歴・メッセージテンプレート管理・テスト送信 |
| **AI経営分析** | ダッシュボード内「今日の一手」— 当日の売上・リピート率・稼働状況からAIが一行で経営アドバイスを生成 |
| **スタッフ管理** | スタッフ一覧・退職処理・アカウント権限管理 |
| **ログアウト** | サイドバー最下部（デスクトップ固定サイドバー・モバイルドロワー両方）。スタッフアプリと共通のログアウト処理 |

> **「Brain分析」について**: 独立した単体画面としては存在しません。「Riora Brain」は本システムの顧客データ基盤（`brain_customers`等のテーブル群）の総称で、顧客管理・スタッフ分析・AI提案など各画面の分析ロジックがこの基盤データを参照しています。顧客一人ひとりのLTV・購入傾向・タイプ分類などを見たい場合は「顧客管理」画面をご案内ください。

## 5. 使い方ガイド

### 4.1 スタッフの1日

```
出勤
 │
 ▼
今日確認 ……… 今日タブを開き、30秒ブリーフィングで本日の予約・注意点を把握
 │
 ▼
接客 ……… Customer Bottom Sheetで顧客情報を確認しながら施術
 │
 ▼
AI提案 ……… 接客の合間に「次にやるべきこと」を確認（離脱リスク・再来提案・商品提案等）
 │
 ▼
接客ヒント ……… 会話に迷ったら、肌タグ・音声AIタグから提案される質問例を参考にする
 │
 ▼
LINE下書き ……… 会計後、LINEメッセージ生成でAI下書きを作成→内容を確認・編集→コピー
 │            → LINEアプリから手動で送信（自動送信はしない）
 ▼
ホームケア ……… ホームケア商品の使い方カード・AI生成メッセージで説明をサポート
 │
 ▼
退勤前確認 ……… メモタブで本日の音声メモが保存されているか確認、マイページで先月比実績を確認
```

**このフローの設計方針**: 各ステップで表示される情報はすべて「事実」または「会話のきっかけ」であり、スタッフに何かを強制する指示・命令ではない。最終判断は常にスタッフ本人が行う。

### 4.2 管理者の使い方（4つのタイミング）

| タイミング | 見るもの | 目的 |
|---|---|---|
| **朝** | ダッシュボード（本日売上見込み・目標進捗・「今日の一手」AIコメント）、失客分析（新規の離脱リスク検知） | 本日の営業方針を立てる。当日中に対応すべき離脱リスク顧客がいないか確認する |
| **営業中** | ダッシュボード（本日売上のリアルタイム推移）、LINE分析（未対応の問い合わせ・配信状況） | 目標に対する進捗を随時確認し、必要ならLINE対応の遅れを解消する |
| **閉店後** | CSV取込（本日分の来店実績取込）、スタッフ分析（各スタッフの当日実績反映確認） | 当日の実績をシステムに反映し、翌日のダッシュボードに正しく載るようにする |
| **月末** | 売上分析・利益分析（月次着地・損益分岐点）、スタッフ分析（前月比成長率）、稼働率分析（月間の稼働状況）、店舗設定（翌月の売上目標更新） | 月次の振り返りと翌月目標の設定を行う |
